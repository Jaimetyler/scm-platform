# Arrival and departure updates

QR and staff check-ins now attempt an immediate McLeod actual-arrival update for the selected pickup or delivery stop. This covers cotton, lumber and other materials at every configured terminal/yard. The source is the server-saved `checked_in_at`, formatted in the yard's local timezone with its DST offset. Scheduled windows are untouched. Existing checkout continues sending actual departure and preserving an existing arrival.

The arrival write uses `PUT /stop/update` with only `__type`, company, stop ID and `actual_arrival`. It does not clear/complete a stop, backfill a remote pickup, deliver an order or set billing status. The generic table-row update contract is documented at https://tms-map.mcleodhosted.com/ws/docs/services?operation=update&role=-1&service=TableRowService . The driver `/dispatch/{stopId}/arrive` operation was rejected because its documented support is LTL only.

A private, RLS-enabled `inbound_arrival_sync` ledger is queued atomically with new physical check-ins. No historical records are backfilled. Saved order, exact yard/direction/selected stop, material and reference are freshly verified before claiming any write. Unmatched and explicitly local/outside-carrier arrivals do not write. Selecting an order later invokes the same sync with the original check-in timestamp. A different pre-existing McLeod arrival is preserved for office review.

The durable claim locks the saved arrival against identity edits and concurrent checkout. A timeout or interrupted write remains fenced: the Active Line's **Check arrival status** action performs read-only reconciliation, never blindly repeats a write. A still-running claim has a one-minute reconciliation hold. Pre-write failures remain pending and show **Retry arrival sync**. Successful writes require a fresh order read confirming arrival and unchanged scheduled windows/statuses. The global `MCLEOD_SYNC_ENABLED` switch is honored; reconciliation can still read when writes are disabled.

Validation: 41 arrival engine scenarios plus a real embedded PostgreSQL migration/permissions test passed. QR route regressions assert that every saved driver arrival invokes arrival sync. Full local suite: 622 passed, 1 skipped, 3 unrelated business-report assertions failed; those same three failures were reproduced on unchanged production commit d242977. Existing synthetic McLeod acceptance passed 65 integration and 41 HTTP adapter assertions. TypeScript passed. Vendor writes in tests are simulated; the first real operational check-in still needs its normal vendor read-back confirmation.
